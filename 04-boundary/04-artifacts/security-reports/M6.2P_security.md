## 4. Egress-safety of the enum — verified airtight (the crown-jewel invariant)

The enum makes the vocabulary real + fail-closed and opens **no** egress, defended in four independent layers
(verified on the code, not assumed):

1. **`permits_external_send(policy)` returns True ONLY for `ALLOW_EXTERNAL`** (validator.py:88-97, `policy is
   ExternalSendPolicy.ALLOW_EXTERNAL` — identity, not `==`). False for INTERNAL_ONLY / BLOCKED_PII / BLOCKED_DEFAULT.
2. **Fail-closed coercion** (`_resolve_send_policy`, validator.py:67-85): a real member → itself; a valid token → its
   member; **None / blank / whitespace / unknown / non-coercible → `BLOCKED_DEFAULT`** — never ALLOW_EXTERNAL, never
   auto-allow. It mirrors `_resolve_sensitivity`'s MISSING→PII. The fail-closed direction is airtight: nothing that is
   not the literal `"ALLOW_EXTERNAL"` token becomes ALLOW_EXTERNAL.
3. **No real registry row is `ALLOW_EXTERNAL`** — the permit-mapping (which events are allowed) is the **OPEN M6-OD-003
   privacy/legal half**, out of scope; every real ACCEPTED event resolves `send_permitted=False`. The gate is reached
   only on ACCEPT (unknown → REJECT False; de-registered / missing-owner → HOLD False).
4. **Defense-in-depth**: `config.EXTERNAL_SEND` is Final `"OFF"` and the staged transport raises `ExternalSendBlocked`
   unconditionally — even an explicitly `ALLOW_EXTERNAL` row opens no real send (an independent choke, unchanged).
