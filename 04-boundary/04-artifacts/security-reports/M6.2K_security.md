## 2. What M6.2K adds, and why the security surface is small

`app/measurement/evidence/` (`smoke_registry.py`, `categories.py`, `models.py`, `gap_blockers.py`,

## 4. The new `evidence/` package — export + disclosure surface

- **No PII on any model.** `SmokeResult` / `CategoryStatus` / `GapBlocker` / `EvidencePack` carry only governance data
  (smoke ids, category names, gap ids like `M6-OD-011` / `M6-P1000`, statuses). The correlation/evidence ids are
  **synthetic** (`corr_0NN` / `ev_0NN` from the test fixture), never customer data.
- **Ids masked at the export choke.** `SmokeResult.to_public()` runs `correlation_id` and `evidence_id` through the
  central `mask()` (RULE-014 / H02); `EvidencePack.to_public()` delegates to the child `to_public()` chokes. The two
  SMK-017 evidence legs assert masked ≠ raw and that the raw id is absent from the public blob.
- **Read-only posture snapshot.** `_posture_snapshot()` reads `config` into a `MappingProxyType`; `EvidencePack` is a
  frozen dataclass. The pack records `BLOCKED/OFF/OFF` + all flags `False`; it writes no enabling value and exposes no
  `pass`/`ready`/`certify`/`sign_off`/`approve`/`enable`/flag-flip verb.
- **Honesty payload cannot be silenced.** `_gap_blockers()` always prepends the 8 canonical `STANDING_GAP_BLOCKERS`
  (governance refs only — no PII) and appends the derived INCOMPLETE/UNRUN gaps; `_readiness()` is fail-closed
  `NOT_READY` on any incomplete category or un-recorded smoke, topping out at `OWNER_REVIEW_REQUIRED` (no Pass/Ready
  member exists). This is the FAIL-007 core, and it holds — consistent with the boundary adversary's 43-vector pass.

## 9. Findings — routed to CODER / owner (all armed-not-fired; none trips FAIL-007; none is a live PII leak)

### F-SEC-2K-1 (primary) — `SmokeResult.status` exported unmasked while the ids are masked
`SmokeResult.to_public()` (`evidence/models.py:49`) masks `correlation_id` + `evidence_id` but emits **`status`
verbatim**. Today `status` is TESTER-set to `"PASS"`/`"FAIL"` (confirmed at `tests/smoke/test_smk_017_p0_evidence_pack.py:48`
`assert smk.status == "PASS"`), so there is **no live leak**. But this is the same **export-masking-scope
inconsistency** family as **F-SEC-2I-2** (funnel `messenger_thread_id` exported raw) and **F-SEC-2J-2** (`buyer_ref`
masked only opt-in): the code masks the ids but not a sibling field on the same export. If a future caller ever set
`status` to a failure string echoing an event payload, a raw phone/email could ride out on the public blob.
*Reachability:* trusted-input only. *Fix:* enum-constrain `status` to `{PASS, FAIL}` **or** route it through `mask()`
on export. This is the M6.2K instance of the OPEN **M6-OD-012** masking-scope decision — which the pack already
discloses as a standing blocker. (= boundary **F-EVID-4**.)

### F-SEC-2K-2 — category completeness uses ref **truthiness**, not shape (hits the security category itself)
`EvidencePackAssembler._categories()` marks a category COMPLETE when `provided.get(k)` is truthy — a whitespace/truthy
ref passes. This matters for the security lens because it applies to **category 9 (SECURITY_PRIVACY)** itself: its own
`no_raw_pii` / `hash_policy` / `access_control` keys would read COMPLETE from a **blank ref**, i.e. the security
evidence could be "present" without content. *Reachability:* trusted-input only — the PM authors `evidence_refs`
(M6-P2007) and **this security review + the judge re-check the actual ref content**, so a hollow security category is
caught downstream, not shipped. *Fix:* validate the ref (stripped-non-blank / existence check) rather than raw
truthiness — the "shape, not truthiness" hardening, applied to the completeness bar. (= boundary **F-EVID-2**.)

### Cross-refs (concur; no PII scope — FAIL-007 hardening for CODER)
- **F-EVID-1** — `recorded` trusts truthiness/duck values (whitespace ids; a duck object exposing `recorded=True`;
  a row appended verbatim so `smoke_id`≠`spec.smoke_id` can mislabel a displayed smoke). *Fix:* pin each row to
  `spec.smoke_id` and require a `SmokeResult` whose stripped `status`+`correlation_id`+`evidence_id` are non-blank.
- **F-EVID-3** — no readiness↔standing-blocker cross-check; a code-exec rebind of `pack_assembler.STANDING_GAP_BLOCKERS`
  could empty the honesty payload while readiness still reads `OWNER_REVIEW_REQUIRED`. *Fix:* assert the 8 canonical
  `STANDING_BLOCKER_IDS` are present (a positive floor). Code-exec-only; not channel-reachable.
