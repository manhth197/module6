## 4. B1 psid_hash — a genuine FAIL-008 reduction (verified on the code)

B1 closes the last raw-PII-at-rest surface on the attribution/live path. Verified:

- **Raw PSID removed from the model.** `AdsAttributionContext` no longer has a `psid` field — it has **`psid_hash`**
  (`attribution_context.py:77`). `to_public()` and `as_stored()` carry only `psid_hash`, and **`as_stored() =
  dict(to_public())`** (line 133) — the durable Zone-B row no longer keeps a reversible raw psid "for trace joins" (the
  M6.2L `mask(psid)` was reversible; the docstring correctly calls it insufficient). This is a real improvement, not a
  relabel.
- **Hashed at the seam.** `resolver.resolve_live_session` (line 104) does `psid_hash=hash_psid(signals.get("psid"))` —
  the raw psid from the (in-process, trusted) signals seam is one-way hashed immediately; the raw value never enters
  the `LiveContext` or the stored context. The raw psid lives only as the `hash_psid` argument (RAM).
- **One-way + fail-closed.** `hash_psid` = `psid_hash:` + base64url(HMAC-SHA256(pepper, psid)) — one-way, deterministic
  per pepper, collision-sensitive. `resolve_pepper` **fail-closes in production** (pepper env unset + production →
  `PsidHashPolicyError`); `production` is an **injectable call arg** defaulting to the immutable `PRODUCTION_FLAG`, so
  the fail-closed branch is testable **without flipping the governance flag** (the SMK-026 test asserts
  `PRODUCTION_FLAG == "OFF"` after).
- **Pepper is a secret_ref.** The real pepper is `os.environ["M6_PSID_HASH_PEPPER"]` (a secret_ref at deploy), used as
  the HMAC key and **never logged, returned, or emitted**. The dev mock is a clearly-labelled non-secret constant used
  only in dev/staged (production fail-closes instead).

**FAIL-008 verdict: does not trip.** No raw PSID on any durable/export surface; the mechanism is one-way and
fail-closed. SMK-026 proves (a) no-raw-in-store, (b) one-way/prefix/deterministic/collision-sensitive, (c)
fail-closed-in-production, (d) None/blank → None.

## 6. F2-6 duck-coerce — security-positive (FAIL-007 + closes a masking-scope leak)

`_smokes` (`pack_assembler.py:154-185`) now rebuilds every provided smoke into a canonical `SmokeResult` from
`getattr` fields, **pinning `smoke_id` to `spec.smoke_id`** and recomputing `recorded` (never trusting a caller

the displayed row is the registry id). So the F-SEC-2K-1/N4 export-masking family **shrinks**: the `smoke_id` slot is
now closed. No PII introduced.

`tests/test_no_http_client_import.py` (attributed to SECURITY_PII / OD-011 sign-off) is an **AST import-scan gate**
that fails the build if any `app/**` module imports an HTTP/egress client (`httpx`/`requests`/`aiohttp`/`urllib3`/
