## 7. Findings (detailed)

### ACCESS-1 — learning-review endpoint must authenticate the owner/marketing reviewer at the M6-OD-011 binding (forward requirement, my emphasis)
See §6. Not a present exposure (staged; inert; no publish executor). **Requirement (owner / M6-OD-011):** authenticate
the caller on the decision path of `POST /api/admin/ads/learning-candidates`, authorize APPROVE to the reviewer role,
and set the recorded `OwnerReviewDecision.actor` from the authenticated identity — never a body-supplied `actor`.

### F-LEARN-PII-1 — owner free-text (`reason`/`audit_ref`/`evidence_ref`) echoed unmasked on export (Observation → CODER + M6-OD-012, my finding)
`OwnerReviewDecision.to_public()` masks `actor` but echoes the three free-text fields. Owner annotations,
contract-non-PII, and excluded from the audit (D5) — **no leak today**. **Fix (CODER):** document the field contract
("owner annotation, non-PII") and/or bound + mask the free-text on the export surface, consistent with the M6.2A
SEC-PII-02 and M6.2G F-SCALE-PII-1 treatment and M6-OD-012.

### F-LEARN-2 / F-LEARN-3 / F-LEARN-4 — input/state validation (MINOR, armed-not-fired) → CODER
- **F-LEARN-2 (untrusted input, my scope):** `score` is checked number-not-bool but not `isfinite`, and `float(10**400)`
  raises an unhandled `OverflowError`, so the admin body escapes the handler's `REJECTED_INPUT` contract. Score never
  gates publish → not FAIL-006. **Fix:** reject non-finite, bound magnitude, wrap `float()` fail-closed.
- **F-LEARN-3 (data integrity):** `review()` does not scrub a caller-supplied `decision` (in-process; the API build
  path has none). **Fix:** reset `decision=None` on review.
- **F-LEARN-4 (untrusted input):** `StrategyMapping` anchors on truthiness only; `run()` writes no Core value
  (RULE-013 holds). **Fix:** validate `sku_ref` against a sellable-SKU set; reject value-shaped `verified_revenue_ref`.

### Cross-reference (concurred; in-process only)
**F-LEARN-1** — `ReviewQueue.update()` re-persists any same-id record with no transition/safe-range validation, so an
in-process caller can swap a forged APPROVED+WITHIN record in. **Not wire-exposed** (the API never calls `update()`)
and **inert** (no publish consumer). The M6.2H analog of the M6.2G store-laundering finding. **Fix (CODER + M6-OD-011):**
reject illegal transitions (or re-force UNKNOWN while the flag is False); the persistence binding must never auto-wire
the queue to a sender.

### FAIL-006 / RULE-011 — corroboration (the in-scope pillar)
FAIL-006 is held (boundary executed; concurred from code — no publish executor, `is_publish_authorized` has zero
consumers, review fail-closed, no learn→publish bridge, body can't fake state). Guarded learning holds: Learn refuses
before a canonical seed; consumes only DQ-PASS+verified signals (no raw channel text → **no prompt-injection surface**);
libraries reject non-canonical seed sources; content fill is BLOCKED (OD-007); no Core-owned write surface (RULE-013/018).

### Untrusted-input handling
The create handler validates the body server-side (target_dim/kind/sku_ref/score) and builds the candidate itself; the
residual gaps are F-LEARN-2 (score crash) and F-LEARN-4 (mapping anchor), routed. No untrusted value publishes anything
or reaches a sink unmasked; no channel-origin text is ingested or interpreted.
