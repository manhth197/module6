### F1 — [MAJOR · re-confirmed + extended] the "forgiving seam" does not turn **every** callee exception into an audited deny
**Files**: `ingest.py:138-139` (identity `resolve`, unwrapped), `ingest.py:194` (registry `validate`, unwrapped),
`ingest.py:228` (store `append`, unwrapped), `ingest.py:183`→`resolver.py:46-61` (`subject_matches`, unwrapped),
`ingest.py:201-209` (the `normalize_ts` wrap catches **only** `ValueError/AttributeError/TypeError`).
**Rule/gate**: RULE-001 audit obligation; SMK-001 "audit rõ" · **Direction: data loss + lost audit** (never a grant).

The Round-3/4 seam is explicit about its own standard (`ingest.py:6-14`, quoted verbatim):

```
… an exception escaping `ingest_event()` means no `IngestResult`, no log line, and — worst — NO audit record …
So `ingest_event()` WRAPS every call that touches external / untrusted data and turns each failure into an
AUDITED DENY … `ingest_event()` itself never raises on hostile input …
```

Only `ConsentReader.get()` is actually wrapped. Two gaps remain, **both executed** (harness group `T`/`N`):

- **(a) throwing-adapter half of MAJOR-6 — still open.** `T-throwadapter`: a throwing `event_registry`,
  `guest_contacts` (via `resolve`), or `web_event_logs` (`append`) adapter escapes `ingest_event()`:
  ```
  registry.validate -> raise (audit=0)   identity.resolve -> raise (audit=0)   store.append -> raise (audit=0)
  ```
  `subject_matches` (`ingest.py:183`) shares the exposure (unwrapped); it is dominated by the step-0 `resolve`
  escape when the same contacts adapter throws.
- **(b) NEW — the `normalize_ts` catch tuple is too narrow.** `N-ts-escape`: a **valid** event whose channel-origin
  `event_ts` is an extreme-year tz-aware datetime (→ `OverflowError` inside `astimezone`) or carries a hostile
  `tzinfo` whose `utcoffset()` raises a non-caught exception escapes the seam with **0 audit**:
  ```
  event_ts = year-9999 @ -14h  -> raise (audit=0)      event_ts = hostile tzinfo -> raise (audit=0)
  ```

**Why MAJOR, not a shrug at a 500.** The module itself declared that a raised exception at a measurement seam is
*data loss, not fail-closed*, and rebuilt the seam around that. Judged by its own contract, one throwing adapter or
one extreme timestamp violates it — and the concrete casualty is the audit trace SMK-001 depends on. **Honest
ceiling:** it cannot grant consent, cannot insert an event code, cannot cause egress, and cannot corrupt the
append-only log — the damage is the lost result + lost audit, which is exactly why it is MAJOR and not BLOCKER, and
why **no in-scope fail gate is tripped**.
**Fix (coder)**: wrap `resolve` (step 0), `validate` (step 2), `subject_matches` (step 1) and `store.append` (step 3)
in the same audited-deny pattern already used for the consent reader (distinct reasons, e.g. `IDENTITY_READER_FAILED`,
`REGISTRY_READER_FAILED`, `LOG_STORE_FAILED`); widen the `normalize_ts` wrap to `except Exception` (audited
`TS_NORMALIZE_FAILED`). Do this **before** M6.2B wires the HTTP endpoint.
