## 2. What M6.2K adds, and why FAIL-007 is the whole game

M6.2K carries the entire M6.2J app forward byte-identical and adds one new package — the **evidence-pack assembler**
(`app/measurement/evidence/`): `smoke_registry.py` (18 P0 smokes), `categories.py` (10 doc §22 categories + mandatory
keys), `models.py` (`Readiness` / `SmokeResult` / `CategoryStatus` / `GapBlocker` / `EvidencePack`), `gap_blockers.py`
(8 standing blockers), `pack_assembler.py` (`EvidencePackAssembler.assemble()`). The slice's job is to prove *readiness
for owner review* — so the one gate that matters is **FAIL-007 / RULE-015**: can the assembled pack ever **overstate
readiness** — declare Pass/Ready/Scale-Ready, launder an un-run/un-evidenced smoke as "recorded", mark a §22 category
complete without content, drop a standing blocker, self-certify, or flip a governance flag?

The design defends this **structurally**, and the attacks confirm every layer holds:
1. `Readiness` has **no PASS/READY member** — it tops out at `OWNER_REVIEW_REQUIRED`; "Pass" is unrepresentable.
2. `_readiness` is **fail-closed** — `NOT_READY` iff *any* category incomplete OR *any* smoke un-recorded.
3. A waiver is honored **only for a proposed smoke** — an owner-smoke waiver is stripped (stays un-run).
4. The **8 standing blockers are always disclosed** (bound by-value at import; never dropped, even in a complete pack).
5. The **posture snapshot is a read-only `MappingProxyType`**; `EvidencePack` is frozen; the assembler has no
   pass/ready/certify/sign_off/approve/enable/flip verb.

## 5. Residuals (armed-not-fired) — route to CODER / M6-P2006

**None trips FAIL-007 from any reachable path.** Every residual is the same shape: the assembler applies a
**truthiness / trust** test where a **validity/shape/type** test would be stricter, and the enabling input arrives only
from a trusted upstream role (TESTER-authored `smoke_results`, PM-authored `evidence_refs`) or from in-process
code-exec — never from a channel. These are hardening opportunities, not open gates. The independent completeness
critic sharpened F-EVID-1 (X1/X2) and surfaced F-EVID-3 and F-EVID-4 that my first pass had not — worth recording
verbatim so the CODER closes the whole family, not just one instance.

- **F-EVID-1 (primary) — the assembler trusts truthiness/duck values instead of a validated run-trace.** Three
  instances: a **whitespace** `status`/`correlation_id`/`evidence_id` reads as recorded (B3); a **duck-typed** object
  exposing `recorded=True` with no trace and `waived=False` is counted and never stripped (X1, the cleanest single-object
  launder — it dodges both the id conjunction and the waiver strip); and a result is **appended verbatim** so its
  `smoke_id` (not `spec.smoke_id`) can mislabel/duplicate a displayed row and hide another (X2). *Reachability:*
  trusted-input only — `smoke_results` is TESTER-built frozen `SmokeResult`s; no channel supplies objects. *Fix:* pin each
  row to `spec.smoke_id`, and require the value be a `SmokeResult` whose stripped `status`+`correlation_id`+`evidence_id`
  are all non-blank before `recorded` is True (the evidence-honesty analogue of the F-GROWTH-* "shape, not truthiness"
  hardening).
- **F-EVID-2** — a category is marked COMPLETE from a **whitespace** evidence ref (E1). *Reachability:* trusted-input
  only — the PM authors `evidence_refs`; security (M6-P2006) + the judge re-check ref content. *Fix:* validate the ref
  shape (stripped-non-blank, or an existence check) rather than raw truthiness.
- **F-EVID-3 — no readiness↔standing-blocker cross-check.** `_readiness` reads only categories+smokes, never
  `gap_blockers`, so a code-exec rebind of `pack_assembler.STANDING_GAP_BLOCKERS` empties the honesty payload while
  readiness still reads `OWNER_REVIEW_REQUIRED` (X5). *Reachability:* in-process code-exec-only; not channel-reachable.
  *Fix:* assert the 8 canonical `STANDING_BLOCKER_IDS` are all present (a positive floor) so even a tampered payload is
  caught, and/or import the standing set behind a function rather than a rebindable module name.
- **F-EVID-4 — `SmokeResult.status` exported unmasked.** `to_public()` emits `status` verbatim; only the
  correlation/evidence ids go through `mask()` (X7). A status carrying PII would export raw. *Reachability:*
  trusted-input only — the TESTER sets `status` to `PASS`/`FAIL`. *Fix:* enum-constrain `status` (PASS/FAIL) or route it
  through `mask()` on export.
- **Robustness (X3)** — a truthy non-`SmokeResult` / non-`Mapping` input fails **closed by crash** (no pack emitted →
  nothing overstated), but as an unhandled exception. *Fix:* coerce/validate inputs, fail-closed to un-run/empty rather
  than raise.
- **D4 (module-global, carried)** — mutating `config.PRODUCTION_FLAG` in-process makes the posture snapshot echo it.
  *Reachability:* code-exec-only; no channel path writes `config`, and the flag never *declares* readiness. Standing
  residual noted in every slice; owner-controlled integration hardens config immutability outside Module 6.
