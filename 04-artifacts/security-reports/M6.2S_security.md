## 4. The reader — fail-closed, PII-safe, no-HTTP, no-secret (verified on the code)

`registry_feed_reader.py` treats the M3 feed as untrusted and is fail-closed at every layer:
- **Feed-level guards** (`apply`): not-a-Mapping → `feed_error:not_mapping`; `registry_version` not int **or is bool**
  → `feed_error:bad_version` (bool explicitly excluded, line 78); `events` not list/tuple → `feed_error:bad_events`; a
  non-Mapping row → `feed_error:row_not_mapping`; missing/blank `event_code` → `feed_error:missing_event_code`. Every
  reject leaves the version + rows **UNCHANGED** (`_reject`).
- **Staleness no-downgrade**: `version <= self._version` → `stale` (no downgrade, incl. equal); the version bumps + rows
  apply **only** on a fully-valid feed, so a malformed higher-version feed cannot poison staleness.
- **All-or-nothing**: parse **all** rows first, then upsert — never half-applied.
- **Fail-closed resolution** (reusing the M6.2P validator coercers, byte-identical): unknown/None `external_send_policy`
  → `BLOCKED_DEFAULT` (never a fabricated `ALLOW_EXTERNAL`); unknown/None/`SENSITIVE` `data_sensitivity` → `PII` (most
  restrictive); `is_active is True` strict-bool (`1`/`"true"`/`0`/`[]` → False); optional metadata → `None` (never
  invented).
- **RULE-001**: M6 **reads** the Core registry for its own validation; the only mutator is `apply()` — no
  insert/create/write/register/reconcile verb, no invented vocabulary, no enum reconciliation. **No HTTP import, no
  live endpoint, no egress surface.**

Security assessment: **fail-closed and security-positive** — no false progress (FAIL-007), no fabricated permit, no
raw secret (FAIL-008), RULE-001 respected.

## 5. RS5 — the feed is the path `external_send_policy` enters the pack; the reader is a faithful consumer that opens no egress

The registry-feed reader is the mechanism by which `external_send_policy` values (including `ALLOW_EXTERNAL`) flow into

- It **fail-closes unknowns** to `BLOCKED_DEFAULT` (never fabricates `ALLOW_EXTERNAL` from a junk/near-miss token).

  `ALLOW_EXTERNAL` row is inert here — the hard egress controls remain `EXTERNAL_SEND` OFF + the M6-OD-003 permit

## 6. P2 (primary, = boundary F-FEED-PII) — `to_public` echoes free-text metadata; the right fix is an input-side reject, not export masking

`RegistryFeedRow.to_public()` (`models/registry_feed.py:37-47`) exports the 7 governance fields
(`event_code`/`data_sensitivity`/`external_send_policy`/`is_active`/`event_group`/`domain`/`updated_at`) **verbatim**,
with no masking choke. A contract-violating M3 feed that smuggled a PII-shaped value into a free-text-ish field
(`event_group`/`domain`) would export it raw.

**Adjudication (sharper than the boundary's "reject or mask"):** these are **governance identifiers**, not PII —
`event_code` (e.g. `ORDER_VERIFIED`), `event_group`, `domain`, the enum tokens, `is_active`, `updated_at`. They **must**
export as-is (masking `event_code`/`event_group`/`domain` would break their purpose — you validate against them, the
same reasoning as `campaign_id`); `PII_FIELDS['EventRegistryRow'] = ()` is correct. So the defense-in-depth is **not
export masking** — it is an **input-side reject** of a PII-shaped value on the free-text metadata (an email-shaped
reject on `event_group`/`domain` at parse time, false-positive-safe — the raw-PII-tripwire pattern), so a
contract-violating upstream cannot land raw PII in a governance field. *Reachability:* armed-not-fired — the feed is a
**trusted Core-owned governance source** (not channel/customer data), `PII_FIELDS` is empty by contract, and (§7) there
is **no durable sink**. → SECURITY M6-P2706 / owner: an input-side PII-shape reject as defense-in-depth against a
contract-violating M3 feed.
