## 3. Verdict on M6-FAIL-006 (auto-publish) — **NOT TRIPPED**

The learning engine cannot auto-publish, for layered, executed reasons:

- **No publish executor exists.** `LearningEngine` exposes only `seed / run / learn / review /
  record_review_decision / guarded_publish_blocked / active_mappings`; the `ReviewQueue` only
  `enqueue/update/get/all/history`; `AdsLearningCandidate` and `LearningDeps` carry no
  publish/auto_publish/go_live/launch/execute/send/dispatch attribute (A1). A token sweep of all six learning
  modules finds **0** publish/action defs and **0** posture-flag writes (E1).
- **`is_publish_authorized` has zero real consumers.** A NAME-token scan of the whole `app/` tree finds the property
  is **read by nothing** outside its own definition (the one other mention is a docstring); the learning package is
  **not imported** by the outbox/scale/dispatcher layers; and a *forged* APPROVED+WITHIN record driven through every
  entrypoint produces **no** publish/sent audit line (W2). The FAIL-006 boundary is structural absence-of-consumer.
- **Review is fail-closed.** `review()` forces `safe_range_status` UNKNOWN while M6-OD-006 is OPEN, so a reviewed
  candidate is HELD unless WITHIN — and it can never be WITHIN while the flag is False (A2); an untrusted WITHIN
  claim is forced UNKNOWN and HELD (A3, SMK-011); even a recorded owner APPROVE leaves `is_publish_authorized`
  False (A4).
- **Config flips don't reach an executor.** Flipping *both* `LEARNING_SAFE_RANGE_RATIFIED` and
  `LEARNING_AUTOPUBLISH_ENABLED` True in-process *can* make `is_publish_authorized` True for a WITHIN+APPROVED
  candidate and unblocks `guarded_publish_blocked()` — **but there is still no publish method**, so nothing publishes
  (A5). The authorization property is flag-gated; the real defence is the structural absence of a publish path.
- **No learn→publish bridge.** `learn()` returns a plain `Dict[TargetDim,float]` — no candidate/promote/emit method;
  a top-scoring (0.99) learned score routed through review+approve is **still** not publishable (score never gates
  publish; the handoff is owner-mediated) (W6).
- **Body can't fake it.** A malicious create body (`review_state=APPROVED`, `safe_range_status=WITHIN`,
  `is_publish_authorized=True`) is ignored — the candidate is built server-side and HELD (D1).

## 4. RULE-011 (guarded learning) & RULE-013/018 (no Core override) — hold

- **Learn precondition:** `learn()` before any canonical seed → `LearningPreconditionError` (B1); it consumes
  **only** usable signals (DQ PASS **and** verified) — HOLD/FAIL/unverified signals are excluded from the scores
  (B2/B3).
- **No fabricated origin:** all six libraries **reject** a non-canonical `seed_source` (B4); an exact-match check
  rejects case/whitespace/substring variants of a canonical token (B6); **content fill is BLOCKED** while M6-OD-007
  is OPEN — any machine content is rejected (framework-only, B5).
- **No Core write:** a `StrategyMapping` must anchor to a sellable SKU (LEX-005; an unanchored mapping raises, C1);
  `run()` is an inert skeleton that records a mapping and runs nothing (C2); the mapping / library store expose **no**
  pricing/program/member-right/CRM/Diamond/Golden-Hour/order-state/commission write method (C3, E1).
- **Owner discipline:** the API requires **all** of actor/reason/audit_ref/evidence_ref and rejects a bad decision
  kind (D2); a terminal candidate cannot be re-decided (D3); the audit detail is **machine-safe** — an owner
  decision whose free-text `reason`/`audit_ref` carries PII does not reach the audit `detail`, and `actor` is masked
  (D5, the coder preempted the M6.2G finding).

## 6. Residuals & notes (none trips FAIL-006; all armed-not-fired)

**F-LEARN-1** *(CODER + M6-OD-011)* — **`ReviewQueue.update()` is a second, unguarded write path (W1).** It checks
only that the id exists; it validates no transition legality or safe-range, so an in-process caller can swap a forged
APPROVED+WITHIN record in, defeating both `review()`'s UNKNOWN-forcing and `record_review_decision`'s terminal guard.
In-process only (`_queue` is a private handle; the API never exposes `update()`) and inert (no publish consumer).
The M6.2H analog of the M6.2G store-laundering finding. **Fix:** `update()` should reject an illegal transition
(or re-force UNKNOWN while the flag is False); the M6-OD-011 binding must never auto-wire the queue to a sender.

**F-LEARN-2** *(CODER + M6-P1706)* — **score under-validated + a crash (W3).** `handle_learning_candidate_create`
accepts NaN/inf as a score, and a huge int (`10**400`) makes `float(score)` raise an **unhandled `OverflowError`**,
so the untrusted admin body escapes the handler's own REJECTED_INPUT fail-closed contract with a 500-shaped crash.
Not FAIL-006 (score never gates publish). **Fix:** reject non-finite scores, bound magnitude, and wrap `float()` to
fail closed.

**F-LEARN-3** *(CODER + M6-P1706)* — **`review()` does not scrub `decision` (W4).** It re-derives `review_state`
(good — a forged APPROVED is discarded) but leaves a caller-supplied `OwnerReviewDecision` on the queued CANDIDATE
record, so `to_public()` could show a forged owner decision on a not-yet-decided candidate. Inert. **Fix:** reset
`decision=None` on review.

**F-LEARN-4** *(CODER + M6-P1706)* — **`StrategyMapping` anchor/ref validation (W5).** `__post_init__` enforces only
truthiness of `sku_ref`, so a monetary value, a Core program object, or a policy token passes as the "sellable SKU",
and `verified_revenue_ref` accepts a literal value despite the "never a value" contract. **But `run()` writes no
Core value** (it only appends in-memory; no module wires learning to a Core table) — RULE-013 holds in effect; this
is an input-validation gap only. **Fix:** validate `sku_ref` against a sellable-SKU set and reject value-shaped
`verified_revenue_ref`.

**Notes:**
- **N-1** frozen-candidate `object.__setattr__` (A7) can forge APPROVED+WITHIN, but requires arbitrary in-process
  code execution and publishes nothing (no executor) — a defence-in-depth limit, not channel-reachable.
- **N-2** the no-auto-publish assertion is a hasattr denylist that omits `run`/`activate`/`promote`/`deploy`; the
  engine already ships a public `run` + `active_mappings` (an inert skeleton today) uncovered by that test — a
  future edit making `run()` do real work would pass the guard. Harden the denylist / add a CI guard asserting
  `is_publish_authorized` and `run` reach no send path. PII belt (E2/D5) is clean; the `verified_revenue_ref`/
  `sku_ref` raw export is a M6-P1706 item.
