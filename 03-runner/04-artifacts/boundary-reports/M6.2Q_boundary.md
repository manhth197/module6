## 1. Attack surface & method

M6.2Q adds the "đường-tới-tiền" A5 leg: an **ads-spend import** under a **maker-checker four-eyes** gate
(`import_gate.py`, M6-OD-016 phase-1 CSV only), a **live-session→campaign binding** (`live_session_ads_binding_store.py`),
a set-once **spend record store** (`ads_spend_record_store.py` via `materializer.py`), and a standalone read-only
**`SessionRoasReader`** (`session_roas.py`) computing `CPA = session_spend / verified-order-count` and
`ROAS = verified-revenue / session_spend` per live_session.

The harness drives the real staged classes and, for each claimed breach, **executes the attack and asserts the actual
outcome** before classifying it. Classification:

- **DEFENDED** — the attack was refused / had no effect through a channel-reachable path.
- **OPEN_NONGATE** — armed-not-fired: the weakness is real but is reachable only via in-process code-exec, or via a
  trusted (maker-checker-approved / measurement-store) input, or is not channel-reachable in this staged posture. Routed
  to CODER / owner / security; **does not** trip an in-scope gate here.
- **NOTE** — documented residual, not separately executed as a breach.
- **BREACH** — an in-scope gate (FAIL-007 / RULE-003, or a PII/egress leak from a channel-reachable path) actually trips.

Adversarial ideation ran through a finder+critic workflow (`wa3ljmrqj`); every novel vector was re-executed in the
harness (GROUP N) before classification — none were accepted on description alone.

## 2. What held (DEFENDED — 23)

### Maker-checker four-eyes (GROUP MC)
- **MC1** raw self-approve (checker == maker) → `AdsSpendImportGateViolation`; import stays PROPOSED, nothing materializes.
- **MC2** case/whitespace/uppercase aliases of the maker (`Maker_Ops`, `maker_ops `, `MAKER_OPS`, tab-wrapped) all
  canonicalize (strip + casefold) to the maker → self-approve refused. The prior red-team raw-`==` gap stays closed.
- **MC3** blank / whitespace-only checker → refused (canonical form empty).
- **MC4** a genuinely distinct checker → APPROVED (the gate is real, not a dead refuse-all).
- **MC5** only an APPROVED import materializes; PROPOSED + REJECTED materialize nothing.
- **MC6** re-deciding an already-decided import → refused (no late flip-flop).
- **MC7** the spend record store is SET-ONCE: idempotent re-materialize is a no-op; an altered re-materialize, `update()`,
  and `delete()` all raise (a spend correction must be a new import).
- **MC8** the gate + materializer expose no network/Marketing-API/send/fetch verb (M6-OD-016 phase-1 CSV only).
- **MC10** the untrusted checker free-text (reason/audit_ref) is not echoed into the audit `detail`; the actor is masked
  → the APPROVE is audited machine-safe (no raw PII in the audit trail).

### CPA/ROAS-by-session — the RULE-003 lock (GROUP RO)
- **RO1** a QUOTE_SENT + ORDER_CREATED in-window contribute 0 to verified_orders/verified_revenue (only OV rows count).
- **RO2** the mispair: a revenue_value crafted onto a QUOTE_SENT row is excluded — `_verified` filters on
  `event_code == ORDER_VERIFIED`, so revenue leaked onto a non-verified row never reaches ROAS.
- **RO3** spend > 0 with ZERO verified orders → CPA `None` (no divide-by-zero) + ROAS `0.0` (wasted spend).
- **RO4** no bound spend → `session_spend None` → CPA `None` + ROAS `None` (a genuine 0/0, never a fabricated 0).
- **RO5** spend gating: only the bound + in-window record is session-attributed; out-of-window + unbound-campaign records
  fall to `daily_total()`, never inflating the session's CPA/ROAS.
- **RO6** a campaign-level record (`.mapped is False`, adset/ad None) that is bound + in-window IS included — the gate is
  the campaign-binding, not the 3-id `.mapped` predicate.
- **RO7** window edges inclusive (`spend_date == window_start` and `== window_end` both counted; `<=`).
- **RO8** only APPROVED-materialized spend reaches the reader (a PROPOSED-only import never touches the money math).
- **RO9** purity: reading CPA/ROAS twice mutates neither the measurement store nor the record store (SMK-010 discipline).

### Binding, PII, carried posture (GROUPS BIND / PII / F7)
- **B1** binding is SET-ONCE + campaign-UNAMBIGUOUS: re-binding a session to a new campaign is refused, and binding one
  campaign to a second session is refused → `session_for_campaign` stays unambiguous (spend can't be split/mis-attributed).
- **B2** `primary_campaign_id` is additive: emitted on export but NOT consulted by `is_scale_evidence_eligible` (which
  reads only source_confidence HIGH + conflict NONE) → the A4 grading is unaffected.
- **PII** `uploaded_by`/`decided_by`/`actor`/`bound_by` are masked on `to_public`; campaign_id + spend numbers are exposed
  (campaign-level, not PII); no `@`/phone-shaped token in any export.
- **F7** the carried evidence pack is intact: the F2-6 duck-coerce still rebuilds a lying duck → NOT_READY; `Readiness`
  has no Pass/Ready member (no self-cert path — RULE-015). The A5 spend work added no Pass/advance path.
- **REG** posture immutable: BLOCKED / OFF / OFF, `is_external_send_enabled()` False — the A5 slice flipped nothing and
  opened no egress.

**No in-scope FAIL-007 / RULE-003 gate was reachable from any channel path.**
