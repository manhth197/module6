## 3. Verdict on M6-FAIL-006 (auto scale) — **NOT TRIPPED** (five independent reasons)

The slice cannot scale, and cannot even *authorize* a scale, for five independent, executed reasons:

1. **No executable path exists.** `ScaleGate` exposes only `propose` / `record_owner_decision`; the store only
   `create/get/all/update_state/history`; `ScaleRequestDeps` holds only `{scale_gate, context, audit}`. **No**
   raise-budget / enable-campaign / open-audience / scale / execute / send / publish / dispatch / approve-all /
   auto-approve attribute exists anywhere (A1). A token sweep of all five scale modules finds **0** action defs
   and **0** posture-flag writes (E1).
2. **`is_scale_authorized` is structurally unreachable.** It requires `overall == PASS`, but the **Funnel**
   (M6-OD-002) and **Dashboard** (M6-OD-005) conditions are hard-wired HOLD — *in both branches*. An
   **exhaustive 1296-cell** `ScaleContext` cross-product yields **overall == PASS in 0 cases** (W1); the single
   maximally-favorable context is HOLD (A4).
3. **Config flips don't help.** Flipping *both* `DASHBOARD_ALERT_THRESHOLDS_DEFINED` and `SCALE_MODEL_RATIFIED`
   True in-process still yields overall HOLD — the two conditions' second branches also return HOLD (A5, triple
   fail-closed).
4. **No consumer arms it.** The scale surface reads **no** posture flag (`PRODUCTION_FLAG` / `GLOBAL_GATEWAY_STATE`
   / `EXTERNAL_SEND` / `SCALE_EXECUTION_ENABLED`) to branch into an action, and there is **no** `is_scale_authorized`
   consumer — even a `True` would execute nothing (W6). `conditions.py` references `config` only for the two
   OPEN-decision rows.
5. **Nothing is wire-forgeable.** There is **no** deserializer (`from_public`/`from_dict`/`json.loads`/`pickle`/
   `__setstate__`/`model_validate`) on the scale surface, so every forge/laundering vector requires in-process code
   execution — not a channel breach (W6). Even a recorded owner APPROVE stays not-authorized (A3), and the untrusted
   request body can never fake a condition (conditions come from `deps.context`, server-side — D1).

## 4. RULE-017 (Risk hard veto) & RULE-010/015 (owner-approval discipline) — hold

- **Every one of the 6 Risk locks vetoes** (recall / sale_lock / quality_hold / complaint_p0 / platform_spam_flag /
  crm_suppression): each active → Risk FAIL → overall FAIL (B1, SMK-009). A risk-locked proposal **cannot be
  approved** (B2); a lock active *at approval time* is caught by a fresh re-read and **refused** (B3, SMK-009 neg).
- **Fail-closed re-check (the coder's fix, re-verified):** an empty/partial fresh risk read no longer reads as
  "clear" — with a HOLD proposal it **refuses** (B4). Unobserved risk is HOLD, never PASS.
- **Owner discipline:** the system never self-approves (A2); a REJECT is recorded and is never a scale (C1); a
  terminal request cannot be re-decided (C2); an APPROVE requires budget_cap + rollback + a non-FAIL request (C3),
  and a FAIL (risk-locked) request is refused even with no fresh read (C4). The API requires **all** of
  actor/reason/audit_ref/evidence_ref and rejects a bad decision kind (D2); it surfaces a Risk-veto refusal as
  `APPROVAL_REFUSED`, not a silent pass (D3).
- **Audit is machine-safe (coder PII fix, re-verified):** an owner decision whose free-text `reason`/`audit_ref`
  carries PII does **not** reach the audit `detail` (only `request_id` + decision enum); `actor` is masked (D5).
- **RULE-020:** missing entry evidence → the P3/P5/P6 condition HOLDs → overall HOLD (A7).

## 6. Residuals & notes (none trips FAIL-006; all armed-not-fired)

**F-SCALE-1** *(CODER + M6-P1606)* — **stale-proposal risk fallback (B5).** When the fresh risk read at approval is
**empty**, `_assert_risk_clear_at_approval` falls back to the proposal's Risk condition; a clean proposal (Risk PASS)
then approves even though a *new* lock could be active but hidden by the empty read. No scale is authorized
regardless (overall HOLD), and the API forwards `deps.context.risk_flags` — but the fresh-read veto is only complete
when the fresh read is. **Fix:** require a *complete* fresh risk read to approve (refuse on empty/partial), rather
than falling back to the proposal.

**F-SCALE-2** *(CODER + M6-OD-011)* — **approval laundering / bait-and-switch (W2).** `ScaleRequestStore.update_state`
validates only `request_id` existence; it does not pin `scale_target` / `budget_cap` / `condition_results` to what
the owner reviewed, so an in-process `replace()`+`update_state` can move a genuine APPROVE onto a different, larger
target/budget. In-process only (`update_state` is not wire-exposed; the gate's own path changes only
approval_state/decision/decided_at) and inert today (no executor). It is the closest shape to a real FAIL-006 *if an
executor is ever wired*. **Fix:** `update_state` must reject any transition that mutates target/cap/condition_results
for an existing request (only approval_state/decision/decided_at may change), or hash the approved (target, cap) into
the decision; and the M6-OD-011 persistence binding should **re-run `evaluate_conditions`** rather than trust a
stored `overall_status`.

**F-SCALE-3** *(CODER + M6-P1606)* — **`budget_cap` not validated (W4).** `-1 / 0 / +inf / NaN` all pass as a
"present" cap (the handler checks only numeric-not-bool; `is_scale_authorized` checks only `is not None`). Inert
today. **Fix:** require `math.isfinite(budget_cap) and budget_cap > 0` in the handler and the approval gate.

**F-SCALE-4** *(CODER + M6-P1606)* — **`rollback_condition` presence-only (W5).** A whitespace `' '` satisfies the
RULE-010 cap+rollback safety pairing (a meaningless halt plan). Inert today. **Fix:** content-validate the rollback
condition (min length / structured predicate) rather than accepting any truthy string.

**Notes:**
- **N-1** frozen-record `object.__setattr__` (B6) and **N-2** module-global mutation of `RISK_LOCKS` /
  `REQUIRED_ENTRY_EVIDENCE` (W3) can forge state / disable a veto, but both require **arbitrary in-process code
  execution** (at which point all in-memory invariants are moot) and authorize no scale (overall HOLD, no executor).
  Defense-in-depth limits, not channel-reachable; hardening: source the locks/entry set from a frozen/validated
  registry. Cosmetic: `scale_gate.py` has a **dead** `from app import config` (config unused there).
- PII belt (E2/D5) is clean; the M6-P1606 security review owns the gate.
